# Preflight

Run per task, before its worker works. Each trap below was found in real runs; `hc --skill` and `--help` do not mention them. **Done when** the worker has accepted its task definition and moved to `working`; under `--watch` or `--auto`, its background watcher must also be running.

1. **Resolve the source.** Use the parent of `git rev-parse --path-format=absolute --git-common-dir`: that is the source checkout even from a linked worktree's cwd. Create from it, never from a linked worktree; use the current worktree only when the user asks. If the source stays unresolved, stop.
2. **Pick the base.** The agreed base, unless the task depends on another; then read the `land-change` skill; it decides the landing shape (GitHub stack, or draft layers plus one landing PR) and each layer's base. For `gh stack` mechanics, read the gh skill's `stacked-prs.md`. Carry branch and base identities into the task definition and maintain dependencies as they change. Authorized publication opens PRs from the same branches and worktrees, never a parallel set; keep backup refs when recovery points are needed.
3. **Create the worktree.** Name the agent first: `w-` plus a stem derived from the task, lowercase, matching `[a-z][a-z0-9_-]{0,31}` in total, the stem `<issue-id>-<slug>` when the task has a ticket (`w-a2a-140-cache-keys`), a concise slug otherwise (`w-review-457`). The prefix is the role: `w-` worker, `r-` its reviewer; prefix bare numeric IDs with `gh-`; unique among live terminals in `hc ls`, with a short hyphenated discriminator on a collision. Choose the branch by repository convention. Create the worktree at `~/.herdr/worktrees/<repo>/<agent>`, never inside the source checkout: `git -C <source> worktree add -b <branch> <path> <base>` for a new branch, `git -C <source> worktree add <path> <branch>` for an existing local branch. An existing local branch ignores the base: when the worktree must sit at a remote head, `git fetch`, then `git -C <path> reset --hard origin/<branch>` on the fresh, clean checkout, and confirm `git -C <path> rev-parse HEAD` equals `origin/<branch>`. Confirm the path in `git -C <source> worktree list`.
4. **Re-pull and claim.** After a free slot is confirmed, run the first-dispatch path in [import.md](import.md); a hold, closed remote ticket, non-ready bead, or lost claim race stops dispatch. Local ad-hoc beads use the same readiness check and native claim, without a tracker pull. For a batch ticket, refresh the batch bead once, before its first target dispatch, with `scripts/import-ticket.sh` without `--dispatch` (it never claims the parent; after its shared fields are written it is never pulled again), create or reuse one child batch target bead per target (`key=<slug>-<target>`), then check each selected target's readiness and claim it with `bd update <target> --claim --actor w-<key>`. Never claim the batch parent.
5. **Write the task definition** into the bead fields per [delegation-contract.md](delegation-contract.md), including `Broad run:` in acceptance and native dependencies. For a batch, write the shared fields on the batch bead and the per-target fields on each claimed target. After the pre-dispatch claim, record `worktree`, `branch` and `base` metadata. Do not write a brief file.
6. **Start the worker** with `scripts/start-worker.sh <name> <worktree> <bead> [--kind <kind>]`, after reading the section for its kind in [agent-quirks.md](agent-quirks.md). The script starts the agent as a hidden background `hc` terminal, your child, in the worktree, with `AGENT_BROWSER_NAMESPACE=<name>` so reaping closes only its browsers, `--outlive-parent` so it survives your session, a `space=<id>` label with your space so herdr-app's spaces sidebar lists it there, and explicit `BEADS_ACTOR=<name>`, `ORCH_BEAD=<bead>`, `BEADS_DIR` and `BEADS_DOLT_SHARED_SERVER` environment values (hc does not inherit the caller's environment). Its `orch-context=<absolute worker-context.sh path>` label enables Pi/Claude recovery after compaction. The short first prompt loads `orchestrated-worker`, runs `bd prime` and `bd show <bead>`, and works that bead; an `r-` reviewer instead reviews per its own `event=re-instructed agent=<name>` comment ([supervise.md](supervise.md)). Pi adds `$skill:orchestrated-worker`, literal `$skill:` tokens from design (a reviewer's from its own comments) and final `ulw`; Claude/Codex are told to load the skill. It exits 0 once the agent is `working` or has taken a turn. Exit 2 means the first prompt is unconfirmed: read the screen with `hc read <name>`; answer a startup dialog per agent-quirks.md, then confirm `working`, or send the bead bootstrap pointer only after reading shows it never arrived. Exit 3 for an `r-` name means a live non-reviewer terminal is `working` in the same canonical worktree; wait for it to settle before starting the reviewer. Any other error is a failed startup (Failures). Under `--watch` or `--auto`, launch is done only when the worker is `working` **and** its `scripts/watch-agent.sh <name>` background task is running ([supervise.md](supervise.md)); a successful script exit alone does not finish launch.

## Failures

A failed or uncertain worktree, startup, or task definition: report the details `git` or `hc` returned and stop that task, leaving an uncertain side effect in place.
