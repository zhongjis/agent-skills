# Preflight

Run per task, before its worker works. Each trap below was found in real runs; `hc --skill` and `--help` do not mention them. **Done when** the worker has accepted its brief and moved to `working`.

1. **Resolve the source.** Use the parent of `git rev-parse --path-format=absolute --git-common-dir`: that is the source checkout even from a linked worktree's cwd. Create from it, never from a linked worktree; use the current worktree only when the user asks. If the source stays unresolved, stop.
2. **Pick the base.** The agreed base, unless the task depends on another; then read the `land-change` skill; it decides the landing shape (GitHub stack, or draft layers plus one landing PR) and each layer's base. For `gh stack` mechanics, read the gh skill's `stacked-prs.md`. Carry branch and base identities into briefs and maintain dependencies as they change. Authorized publication opens PRs from the same branches and worktrees, never a parallel set; keep backup refs when recovery points are needed.
3. **Create the worktree.** Name the agent first: lowercase, derived from the task, matching `[a-z][a-z0-9_-]{0,31}`, `<issue-id>-<slug>` when the task has a ticket (`a2a-140-cache-keys`), a concise slug otherwise (`review-457`); prefix bare numeric IDs with `gh-`; unique among live terminals in `hc ls`, with a short hyphenated discriminator on a collision. Choose the branch by repository convention. Create the worktree at `~/.herdr/worktrees/<repo>/<agent>`, never inside the source checkout: `git -C <source> worktree add -b <branch> <path> <base>` for a new branch, `git -C <source> worktree add <path> <branch>` for an existing local branch. An existing local branch ignores the base: when the worktree must sit at a remote head, `git fetch`, then `git -C <path> reset --hard origin/<branch>` on the fresh, clean checkout, and confirm `git -C <path> rev-parse HEAD` equals `origin/<branch>`. Confirm the path in `git -C <source> worktree list`.
4. **Write the brief** ([delegation-contract.md](delegation-contract.md)) to a file outside the worktree.
5. **Start the worker** with `scripts/start-worker.sh <name> <worktree> <brief-file> [--kind <kind>]`, after reading the section for its kind in [agent-quirks.md](agent-quirks.md). The script starts the agent as a hidden background `hc` terminal, your child, in the worktree, with `AGENT_BROWSER_NAMESPACE=<name>` so reaping closes only its browsers, `--outlive-parent` so it survives your session, and the brief as its first message, which keeps `$skill:` text literal. It exits 0 once the agent is `working` or has taken a turn. Exit 2 means the brief is unconfirmed: read the screen with `hc read <name>`; answer a startup dialog per agent-quirks.md, then confirm `working`, or send the brief with `hc send` only after reading shows it never arrived. Any other error is a failed startup (Failures).

## Failures

A failed or uncertain worktree, startup, or brief: report the details `git` or `hc` returned and stop that task, leaving an uncertain side effect in place.
