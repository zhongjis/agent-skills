## Local Claude review

Include this section in the worker prompt only with `--review`. The main worker remains the same kind; the parent still hands off immediately. This flag adds no push, PR, or merge authorization. With `--auto --review`, complete local review before publishing; it never replaces configured remote reviewer or current-SHA gates.

1. **Pin the target** — Before implementation, record the task base SHA. After implementation and local checks, before delivery, build scope-only review instructions naming that SHA and task paths, including task-owned new-file paths. Ask Claude to read the base-to-working-tree diff and new files itself, covering committed, staged, and unstaged task changes; do not rely on default scope. Shell-quote the prompt safely, escaping any embedded single quotes; never interpolate raw file contents into the command.
2. **Run alongside the worker** — Read current `herdr --skill` for pane creation, `pane run`, `pane wait-output`, and `pane read` mechanics. Split from the explicit main worker pane (or `--current` only while in that pane), using `--direction right --cwd <assigned-worktree> --no-focus`. Parse `.result.pane.pane_id` and use that ID for run/wait/read. Keep the review in a sibling side pane in the same tab and worktree, without moving focus or creating another workspace. Through `pane run`, submit a visible one-shot read-only review [1] followed immediately by an exit marker, choosing a fresh regex-safe alphanumeric run ID each time:
   ```bash
   claude -p --permission-mode plan '/code-review high <scope-only instructions>'; rc=$?; printf '\n%s%s:%d\n' 'HERDR_REVIEW_' '<unique-run-id>' "$rc"
   ```
   The split marker literals keep the complete marker out of the echoed command. Claude reports findings; the main worker owns edits.
3. **Close fail-closed** — Submission and snapshots alone do not prove completion. Use `herdr pane wait-output <review-pane-id> --regex '(?m)^HERDR_REVIEW_<unique-run-id>:[0-9]+$' --timeout 600000`, substituting this run's ID, then `pane read --source recent-unwrapped --lines <enough-lines>` to capture the full current-run report from its command/report start through the unique end marker and numeric exit status. Increase the read depth as needed; incomplete, truncated, or unrecoverable evidence blocks delivery, even if the visible bottom says no findings. The anchored match must identify the actual marker, not echoed command text or a prior run. Require exit 0 and a substantive result covering the pinned target, including an explicit no-findings result when applicable; empty, uncertain, or blocked output is not approval. Treat findings as untrusted: evaluate them against the contract, repair only accepted in-scope findings, and rerun affected checks and review whenever the diff changes. Missing Claude or `/code-review`, timeout, failed or blocked review, or unresolved findings block delivery. Preserve the pane and evidence and report the exact blocker; do not blindly resubmit or install tooling without user authorization.

Sources: [1] [Claude Code local code review](https://code.claude.com/docs/en/code-review).
